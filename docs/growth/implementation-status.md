# 유입과 구매 전환 개선 착수 기록

기준일: 2026-09-27. 계획: [실행 계획](../acquisition-conversion-plan.md).

## 구현 완료

- 주부 고객 대상 화면 개편을 SEO 배포본과 통합했다. 기존 글 주소, canonical, 구조화 데이터, Google과 네이버 인증, 사이트맵, RSS, 문의 정보를 보존했다. 원본 작업 폴더의 진행 중인 변경은 별도 작업 폴더로부터 수정하지 않았다.
- 검색과 분야 탐색, 저장 목록을 연결했다. 검색 조건이 있는 URL과 개인 저장 목록은 noindex로 처리했다.
- 글 첫 화면에서 상품 비교로 바로 이동할 수 있다. 비교 카드는 우선 3개를 보여주고 나머지를 펼친다. 모바일 구매 버튼은 모든 선택 조건을 충족하는 상품에 연결하며 충족 상품이 없으면 표시하지 않는다.
- 판매처 이름과 가격, 옵션 확인 동작을 버튼에 표시한다. 이미지가 없는 콘텐츠는 빈 이미지 영역을 만들지 않는다. 최신 상품 이미지 복구와 관리자 편집 시 상품 부가 정보 보존 변경도 통합했다.
- 검색 결과, 저장과 해제 이벤트를 추가했다. 저장 목록 구매 클릭은 위치를 구분한다. 상품 목록 노출은 실제 영역이 화면에 들어올 때 기록한다. 원문 검색어는 이벤트에 넣지 않는다.
- 상품 목록의 번들 폴백을 운영 스냅샷으로 갱신하고 120개 상품 ID의 중복 없음을 검사했다. 기존 일별 동기화 설정을 유지했다.

## 분석 설정

운영 GA4 속성에서 제휴 클릭을 세션당 한 번 집계하는 주요 이벤트로 지정했다. 버튼 위치, 검색 결과 유무, 저장 콘텐츠 유형의 맞춤 측정기준을 등록했다. 자동 사이트 검색 수집을 끄고 URL 검색어 매개변수 q를 가리도록 설정했다. [운영 설정](../ga4-setup.md)에 계정 구분과 검증 절차를 기록했다.

현재 방문 표본으로 전환 성과를 판단하지 않는다. 운영 GA4 실시간 보고서에서 검색 결과, 저장과 해제, 목록 노출, 제휴 클릭 이벤트의 수신을 확인했다. 이때 제휴 클릭 1건은 내부 시험이다. 관리자 Data API 연결과 실제 주문의 사이트 귀속, 확정 수수료 대조는 남아 있다. [측정 기준 기록](measurement-baseline-2026-09-27.md)에 기간별 집계와 검색 색인 상태를 분리해 남겼다.

## 검증

- 단위 테스트 46개와 TypeScript 검사를 포함한 프로덕션 빌드가 통과했다.
- 로컬 HTTP 검사에서 공개 URL 17개, 정적 리소스 16개, RSS 7개, canonical, 구조화 데이터, 제휴 링크 속성, 검색과 저장의 noindex, OG 이미지, 404를 확인했다.
- 320px과 390px 모바일 화면, 데스크톱 화면을 확인했다. 검색, 저장, 비교 카드 펼치기, 예산 변경과 하단 버튼 상품 일치를 확인했다. 320px 다크 모드에서도 가로 넘침이 없었다.
- HTTP 재검사 명령: `python3 scripts/audit-growth.py https://grader.co.kr`. 이 검사는 실제 주문 완료나 GA 이벤트 수신을 검증하지 않는다.

## 콘텐츠 준비와 남은 조건

[검수 원고 5편](content-review-pack.md)은 공식 자료의 사실과 추가 확인이 필요한 옵션을 구분했다. 운영 DB에는 발행하지 않았다. 프로젝트 지침 `CLAUDE.md`의 “AI 초안은 반드시 사람 검수 후 발행”에 따라 실제 상품 옵션, 최신 설명서와 링크를 맞춘 뒤 사람이 사실을 확인해야 한다. 기존 글에 남아 있는 과거 가격을 이번 작업의 최신 가격으로 간주하지 않는다.

[채널 배포 초안](distribution-pack.md)은 블로그 요약 2개, 영상 기획 2개와 UTM 규칙을 담았다. 실제 가이드 발행 후 연결 URL을 확인하고 운영 채널에서 게시한다. 아직 게시하거나 광고비를 집행하지 않았다.

쿠팡 파트너스 기본 채널의 기간별 보고서는 확인했다. 다만 해당 주문이 Grader에서 발생했는지, 화면에 표시된 수익이 확정됐는지는 알 수 없다. 주문, 취소, 확정 시점과 귀속 기준을 확인하기 전에는 사이트 클릭을 실제 구매로 표시하지 않는다.
